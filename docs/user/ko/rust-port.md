# Rust 포팅

이 저장소의 기기 런타임은 Rust로 옮긴 당근파일럿입니다. 원본은 `ajouatom/openpilot`의 `carrot-wip`입니다.
모델을 준비하는 Python과 기존 C/C++ 라이브러리·Panda 펌웨어는 그대로 씁니다.

## 지금 상태

- 원본의 기능이 전부 옮겨진 것은 아닙니다. 빠진 기능과 원본과 다르게 동작하는 부분은 저장소의 `docs/md-upstream-port-gaps.md`, `docs/md-current-state-review-20261111.md`, `docs/md-port-handoff.md`에 있습니다.
- 빌드되고 부팅된다는 것이 주행 검증을 뜻하지 않습니다. 각 변경은 그 커밋으로 실제 주행한 결과가 있어야 확인된 것입니다.
- 브랜치는 둘입니다. `dev-md`는 운전자 모니터링까지 포함하고, `dev`는 운전자 모니터링이 동작하지 않는 시험용입니다. 두 브랜치의 변경은 섞지 않습니다.

## 기기에서 받고 빌드하기

기기는 시작할 때 바뀐 부분만 스스로 컴파일한 뒤 실행합니다. 따로 내려받는 실행 파일은 없습니다.

1. 차를 세운 상태에서 기기의 `/data/openpilot`을 원하는 커밋으로 갱신합니다.
2. openpilot을 다시 시작하면 컴파일이 시작됩니다. 진행 상황은 화면과 `/data/openpilot-build/build.log`에 나옵니다.
3. 로그에 `Build complete`가 나오면 끝난 것입니다. 바뀐 범위에 따라 몇 분에서 십여 분이 걸립니다. 처음 설치할 때는 더 오래 걸립니다.
4. 컴파일이 끝나기 전에 전원을 끊거나 다시 갱신하지 마세요. 갱신 직후에는 `sync`를 실행해 두는 것이 안전합니다.

메모리가 모자라 컴파일러가 중단되면 동시에 돌리는 작업 수를 6, 4, 3, 2로 줄여 가며 이어서 시도합니다. 로그에 `Compile stopped with 6 jobs`가 보여도 그 뒤에 `Build complete`가 나오면 정상입니다. 끝까지 실패하면 화면에 오류와 로그 끝부분이 표시되고 openpilot은 시작되지 않습니다. 이때는 같은 로그를 보고, 이전에 빌드된 복구 서비스가 있으면 6999번 포트로 접속할 수 있습니다.

예전 안내에 있던 CPU 계측 도구(`cpu-sample`)는 없어졌습니다.

## 폰·Jetson 외부 모델

외부 기기에서 주행 모델을 돌리는 Jetlink의 동작은 [Jetlink 안내](jetlink.md)에 있습니다. 켜고 끄는 설정이나 Shadow 모드는 없으며, 준비되면 정차 중이거나 핸들을 잡은 상태에서 스스로 넘어갑니다.

호환 호스트에는 저장된 Wi-Fi 프로필을 비공개 Jetlink 연결로 전달하며 호스트 준비가
끝난 뒤 추론을 시작합니다. Wi-Fi 암호는 상태 파일과 로그에 남기지 않습니다.
레거시 호스트가 지정된 모델을 요청하면 다운로드를 검증한 뒤 전송하며,
온로드로 전환되거나 케이블이 분리되면 준비를 중단합니다.
