# 실험용 Rust 포팅

이 문서는 초기 계측 도구와 기기 자체 빌드 작업(#598)을 안내합니다.
아래 CPU 계측 도구는 차량 프로세스를 대체하거나 추가 AI 모델을 활성화하지 않습니다.

Rust 1.94.0이 설치된 Linux 개발 호스트에서 `rust/` 디렉터리로 이동해 실행합니다.

```sh
cargo run --release --locked --bin cpu-sample -- 1000
```

선택 인자는 측정 간격이며 1~60000밀리초, 기본값은 1000입니다. TSV로 출력합니다.
100%는 논리 코어 하나 기준이므로 멀티스레드 프로세스는 100%를 넘을 수 있습니다.
processor 열은 마지막으로 관찰된 메인 스레드의 코어이며, 프로세스 affinity나 모든
스레드의 배치가 아닙니다. 읽을 수 없거나 종료된 프로세스와 유효하지 않은 카운터
차이는 제외합니다. 짧은 측정 간격에서는 시간 카운터의 해상도 한계가 큽니다.

이 도구는 한 번 측정하는 진단 도구이며 상주 서비스가 아닙니다. 차량 명령을 발행하지
않습니다. 호스트 테스트와 일반 aarch64 빌드 성공은 AGNOS 호환성, CPU 절감, 온도 개선,
차량 안전 검증을 뜻하지 않습니다. 일반 CI 빌드를 차량에 설치하지 마세요. 대상 기기
검증은 아직 남아 있습니다.

### 콤마 자체 빌드 준비 작업 (#598)

모델 준비는 기존 Python 경로를 유지하며, 성능 개선과 전체 런타임 재다운로드 없는
자체 빌드를 우선 개발합니다. `openpilot-runtime-build`는 고정된 네이티브 Rust 1.94.0과
오프라인 Cargo 의존성으로 필요한 대상을 빌드합니다.
진행과 수용 조건은 [#598](https://github.com/bin9208/openpilot-rust/issues/598)에서 확인합니다.

현재 작업 브랜치의 ARM 시작 경로는 소스 빌드를 선택하며, 해당 커밋의 전체 runtime
release를 자동으로 내려받아 대체하지 않습니다. 기존처럼 Git 설치·업데이트 후
재시작하는 흐름으로 연결했습니다. 고정된 빌드 입력과 기본 설정을 Git 브랜치에 함께
포함합니다. 최초 시작에서 필요한 도구와 의존성을 자동으로 준비하며, 이후에는 공통
캐시를 재사용합니다. 정확한 시험 후보 커밋과 확인 결과는 위 #598에서 확인합니다.
일반 시작은 진행 화면과 6999 복구 서버를 먼저 띄우고, 준비된 의존성과 Cargo 캐시로
변경분을 컴파일한 뒤 manager를 시작합니다. 컴파일 사이의 전체 SDK·산출물 감사,
seal, 세대 패키지 보관은 개발용 명시 실행으로 분리합니다. 변경 없는 시작은 준비와
컴파일도 건너뜁니다. 실패하면 오류 화면과 로그 경로를 표시하고 복구 서버를 유지합니다.
초기 의존성 설치가 필요한 경우에는 기존 다운로드·입력 준비가 한 번 필요합니다.
검사 정책과 아직 실측하지 않은 항목은 [#689 기록](../../naver/user-startup-689.md)에 남깁니다.

기기 시험은 #598에 안내한 후보를 기존 Git 설치·업데이트 방식으로 받은 뒤 재시작합니다.
Rust 설치나 별도 입력 준비 명령은 필요하지 않습니다. 소프트웨어 화면의 커밋을 확인하고,
정상 화면·녹화·기존 로그 업로드를 확인합니다. 최초 설치와 작은 수정 후에는 각각 Git 수신
시작부터 화면 표시까지 시간을 따로 기록합니다. 실제 기기 결과는
[#528](https://github.com/bin9208/openpilot-rust/issues/528)에 남기며 CI 시간을 기기 실측으로 사용하지 않습니다.

개발용 `openpilot-runtime-assets --plan JSON --cache DIRECTORY`는 계획에 명시된
HTTPS 자산을 SHA-256·바이트 수로 확인해 내용별 캐시에 저장합니다. 같은 자산을
다시 준비하면 HTTP 전송량은 0이며, provider 하나를 변경하면 그 자산만 받습니다.
보고서의 `transferred_bytes`는 HTTP 본문 바이트 수입니다. 이 도구는 압축 해제나
장치 설치를 수행하지 않습니다. 빌드 도구는 깨끗한 Git checkout을 요구하고 실제
커밋·tree·recipe·compiler·linker·실행 파일 해시를 보고서에 남깁니다.
실제 입력을 포함한 최초·변경 후 시작 결과와 사용자 기기 수용은 별도로 확인합니다.

본문을 받기 전 일시 연결 오류는2·4·8초 간격으로 최대3회 재시도하며, 전체 전송
시간은1800초 이내로 제한합니다. 일부 본문을 받은 뒤 실패하거나 HTTP·크기·해시
검증에 실패하면 오류를 반환하고 기존 자산과 정상 실행 세대를 보존합니다.

압축을 푼 toolchain/provider는 `openpilot-runtime-inputs --root INPUT_TREE
--output RECEIPT_JSON`으로 실제 파일 hash·크기·권한·내부 파일 symlink 목록을
기록할 수 있습니다. 이 기록을 독립적으로 확인한 자산 출처에 연결한 뒤, recipe의
`inputs`에 receipt SHA-256을 고정하고 `input_trees`에 tree 경로와 receipt 경로를
지정합니다. 이 명시적 개발용 감사 경로는 빌드 전후 실제 tree의 변조·추가·누락을 거부합니다. receipt를 새로 만든
사실만으로 입력을 신뢰하지 않으며, 기록이 없는 tree는 검증된 것으로 계산하지 않습니다.
검사별 예상 결과와 최종 기기 수용 절차는 [검증 안내](../../naver/native-build-test-guide-598.md)를 참고하세요.
