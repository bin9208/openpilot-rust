# 실험용 Rust 포팅

이 독립 저장소에서는 오픈파일럿 기기 런타임의 Rust 전환을 시작했습니다.
첫 workspace에는 스칼라 필터와 Linux CPU 계측 도구가 있습니다.
아직 차량 프로세스를 대체하거나 추가 AI 모델을 활성화하지 않습니다.

Rust 1.94.0이 설치된 Linux 개발 호스트에서 `rust/` 디렉터리로 이동해 실행합니다.

```sh
cargo run --release --locked --bin cpu-sample -- 1000
```

선택 인자는 측정 간격이며 1~60000밀리초, 기본값은 1000입니다. TSV로 출력합니다.
100%는 논리 코어 하나 기준이므로 멀티스레드 프로세스는 100%를 넘을 수 있습니다.
processor 열은 마지막으로 관찰된 메인 스레드의 코어이며, 프로세스 affinity나 모든
스레드의 배치가 아닙니다. 읽을 수 없거나 종료된 프로세스와 유효하지 않은 카운터
차이는 제외합니다. 짧은 측정 간격에서는 시간 카운터의 해상도 한계가 큽니다.

이 도구는 한 번 측정하는 진단 도구이며 상주 서비스가 아닙니다. 차량 명령을 발행하지
않습니다. 호스트 테스트와 일반 aarch64 빌드 성공은 AGNOS 호환성, CPU 절감, 온도 개선,
차량 안전 검증을 뜻하지 않습니다. 일반 CI 빌드를 차량에 설치하지 마세요. 대상 기기
검증은 아직 남아 있습니다.

`dev-md`의 네이티브 Jetlink 후보는 각 앱 세션을 오프로드에서 선택한 모델에 고정합니다.
Shadow에서는 기본 모델이 제어를 유지하며, 활성화에는 여전히 동일 기기·수치 검증
기록과 기존 정차·제어 해제 조건이 필요합니다. 준비 완료, 호스트 테스트와 ARM 에뮬레이션은
이 기록을 대신하지 않습니다. [Jetlink 설정](settings.md#jetlink-외부-모델-실험)을 확인하세요.

호환 호스트에는 저장된 Wi-Fi 프로필을 비공개 Jetlink 연결로 전달하며 호스트 준비가
끝난 뒤 추론을 시작합니다. Wi-Fi 암호는 상태 파일과 로그에 남기지 않습니다.
레거시 호스트가 지정된 모델을 요청하면 다운로드를 검증한 뒤 전송하며,
온로드로 전환되거나 케이블이 분리되면 준비를 중단합니다.

`dev-md` 네이티브 업데이터는 현재 브랜치에 설정된 Git 원격 저장소를 업데이트 확인,
브랜치 목록 조회, 다운로드 및 다운로드한 대상의 추적에 일관되게 사용합니다.
예를 들어 `rust/dev-md`를 추적하는 브랜치는 같은 복제본에 `origin`이 있어도
`rust`에서 다운로드합니다. 업데이트 대상 브랜치를 바꿔도 현재 브랜치의 원격
저장소를 유지합니다. 브랜치 원격 설정이 없는 경우에만 `origin`을 사용합니다.
명시한 원격 저장소가 없거나 로컬·미지원 형식이면 다른 저장소로 전환하지 않고
업데이트가 실패합니다. HTTPS, HTTP, SSH(`git@host:path` 포함), Git 네트워크
전송을 지원하며 로컬 경로, `file://` URL 및 로컬·미지원 형식으로 바꾸는 URL
재작성 설정은 거부합니다. 새 설정은 필요하지 않습니다. 기기 업데이트 수용 검증은
아직 남아 있습니다.
