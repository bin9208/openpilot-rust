# Android Jetlink 실험 앱

대상은 갤럭시 탭 S9 울트라 12GB(Android 15 이상)와 comma 3X입니다. 앱은 arm64 Android 9 이상에서 설치 가능하도록 빌드하지만, 다른 기기 호환성과 대상 기기의 실측은 별도 검증 사항입니다. 현재 단계는 모델·연결 검증용이며 차량 사용 승인이 아닙니다.

## 설치와 모델 가져오기

1. 제공된 APK와 SHA-256을 대조한 뒤 APK를 탭에서 엽니다. 파일 앱의 외부 앱 설치 권한이 필요할 수 있습니다.
2. `Carrot Jetlink` → **모델** → **모델 패키지 ZIP 가져오기**에서 준비된 패키지를 선택합니다. 모델은 APK에 포함되지 않으며 내부 앱 저장소에 검증 후 저장됩니다. 가져오기는 모델 용량 외 임시 공간이 필요합니다.
3. 패키지는 `manifest.json`, `model.onnx`, 선택적 `benchmark.frames.bin` 순서의 ZIP입니다. 경로·크기·SHA-256·입출력 형상·상태 연결을 검사합니다. CTV3의 원본 바이트를 보존한 stateful 패키지를 사용합니다. queued 모델은 수치 일치 검증 미완료로 거부합니다.
4. CPU가 초기 기준입니다. NNAPI 선택은 실행 제공자 요청이며 전체 모델의 NPU 가속을 보장하지 않습니다. 실패하거나 일부 연산이 CPU에서 실행될 수 있습니다.

업데이트할 때 앱을 삭제하거나 데이터를 지우지 마세요. 같은 서명으로 만든 APK를 덮어 설치해야 모델 데이터가 유지됩니다. CI 임시 debug APK는 실행마다 서명이 달라질 수 있으므로 배포용 로컬 APK와 섞어 업데이트하지 마세요.

## 정차 상태 벤치마크

**벤치마크** → **100프레임 속도 측정**를 실행합니다. 화면을 켜 둔 채 기다리세요. 준비·워밍업 후 실제 ONNX Runtime 추론 시간을 측정합니다. 입력은 패키지의 합성 프레임을 반복하거나 검은 이미지와 고정 문맥을 사용합니다. 평균/p50/p95/p99/최대값과 50ms 초과 횟수를 표시합니다. 백분위는 최근 2,000개, 평균·최대·초과 횟수는 전체 실행 기준입니다.

**출력 비교 ZIP 저장 (벤치마크 후)**로 첫 입력 묶음의 실제 출력을 저장합니다. 패키지 입력은 최대 100프레임이며 초과하면 가져오기를 거부합니다. ZIP을 PC에서 풀고 `tools.jetlink_model.compare`로 동일 입력의 PC 기준 기록과 비교합니다. **진단** → **진단 보고서 저장**으로 기기/모델/요청 제공자/성능·발열 정보를 저장합니다. 측정값은 실행 시작 당시 모델·제공자를 유지하며 나중에 선택을 바꿔도 바뀌지 않습니다. 발열·메모리는 내보내는 시점의 값입니다. 카메라 영상이나 위치는 진단 파일에 기록하지 않습니다.

측정 시간에는 C3X 카메라 변환과 전체 USB 왕복이 포함되지 않습니다. APK 빌드·합성 입력 성공은 실제 탭 성능, 30분 발열 또는 차량 검증을 대신하지 않습니다.

## USB 연결과 중지

C3X에는 Jetlink 통합이 포함된 브랜치가 필요합니다. 앱만 설치해서는 연결되지 않습니다. 정차하고 크루즈·조향을 포함한 모든 제어를 해제한 상태에서 Carrot Web의 `시스템 → Jetlink 외부 모델 → Jetlink 모드`를 **외부 GPU 모델(1)**로 선택합니다. 현재 세션이 준비되고 모델 계약이 일치하면 실제 외부 모델 출력을 사용합니다. 별도의 Shadow 옵션이나 1 → 2 활성화 단계는 없습니다. 기본값은 **끄기(내부 모델, 0)**이며 관리 프로세스 재시작·재부팅 시 0으로 돌아갑니다. 기존 저장 값 1과 2는 모두 외부 모델 요청으로 해석합니다. 웹 화면은 2도 같은 외부 모델 선택으로 표시하며 단순 조회로 값을 다시 쓰지 않습니다.

USB 3 데이터 케이블을 연결하고 기기의 Jetlink USB 준비 후 앱의 **상태** → **comma USB 연결**을 눌러 USB 권한을 허용합니다. 앱은 알림을 표시하는 연결 서비스를 사용합니다. Android 직접 USB bulk 연결에는 호스트 IP가 필요하지 않습니다. 웹 카드는 호스트가 실제 주소를 전달할 때만 IP를 표시하며 연결·모델 오류는 그대로 보여 줍니다. 앱의 CPU·NNAPI 선택은 앱 추론 백엔드 설정이며 C3X의 Jetlink 모드를 켜지 않습니다.

AGNOS 기본 ADB USB가 같은 컨트롤러를 쓰고 있으면 Jetlink를 사용하는 동안 일시 해제합니다. 저장된 ADB 설정은 유지하며 Jetlink를 끄거나 준비에 실패하면 현재 설정에 맞춰 복원합니다. 이때 USB ADB 연결은 끊어질 수 있습니다. 다른 USB gadget이나 eGPU 소유권을 강제로 해제하지 않습니다.

권한을 거부하거나 케이블을 분리하면 수동으로 다시 연결해야 합니다. **중지** 또는 알림의 **중지**로 서비스를 종료합니다. 재부팅/프로세스 종료 후 자동 연결하지 않습니다. 발열 단계 SEVERE 이상은 작업을 중단하며 식힌 뒤 다시 시도합니다. 메모리 부족·모델 오류는 상태 화면에 표시합니다. 엔진 `ready`는 주행 허용 상태가 아닙니다.

실기 검증 전 확인 항목: APK 설치/회전, 모델 가져오기, CPU 및 NNAPI 출력 비교, USB 권한 거부·분리·재연결, 30분 지연·발열 상태, C3X 전체 50ms 지연·소실 시 제어 해제. 테스트 후보를 선택했다는 사실은 이 결과를 입증하지 않습니다. 이슈 #44/#45/#46/#47의 실기 항목은 결과가 나올 때까지 열어 둡니다.

## C3X 제어 전환과 검증 경계

외부 모델을 선택하면 정차·제어 해제 조건을 충족한 뒤 현재 외부 예측 결과를 모델 메시지 발행에 실제로 사용합니다. 주행 중이나 제어 활성 상태에서 선택하면 정차·제어 해제까지 기다리며 설정을 다시 바꿀 필요는 없습니다. 외부 활성 중에도 내부 모델은 매 프레임 실행하여 복귀용 상태를 유지합니다. USB 소유 프로세스의 정지/느린 응답은 별도 50ms 통신 제한으로 격리합니다. 전체 예산은 C3X warp 시작부터 외부 응답·해석·발행 직전까지이며 앱 단독 수치와 다릅니다.

명시적으로 외부 모델을 선택할 때 과거 `JetlinkValidation` 승인 프로필은 요구하지 않습니다. 지원되는 현재 세션·모델 계약, 실제 실행 파일 SHA-256 일치, 카메라·제어 입력 준비, 출력 형상·유한값, 현재 프레임·세션 식별과 전체 50ms 제한은 계속 검사합니다. 세션이나 실행 파일이 일치하지 않으면 오류를 표시하고 내부 모델을 유지합니다. 이 선택은 실제 테스트 후보 사용 요청이며 기기·주행 검증 완료를 뜻하지 않습니다.

로그의 `validated`는 과거 검증 증거를 나타내는 별도 값입니다. 일치하는 승인 프로필이 없으면 외부 모델 활성 중에도 false를 유지합니다. 기존 프로필은 모델·기기·백엔드·앱/런타임 식별, 수치 비교와 최소 30분 지연·유실 증거를 계속 대조합니다. 기기·백엔드·버전이 바뀌면 그 증거가 일치하지 않을 수 있으며 승인 결과를 만들어 대신하지 않습니다. 벤치마크 성공만으로 검증 기록을 만들지 않습니다.

활성 중 첫 timeout/분리/잘못된 프레임/NaN은 외부 출력을 폐기하고 소실 상태를 유지합니다. `외부 모델 소실`에 해당하는 no-entry/soft-disable 경로를 사용하며, AlwaysLateral 단독 조향도 소실 상태를 우회하지 않습니다. 내부 모델 성공, 재연결, 정차나 기존 값 1 ↔ 2 변경만으로 소실 상태를 지우지 않습니다. 정차하고 모든 제어를 해제한 뒤 **끄기(0)**로 확인하고 **외부 GPU 모델(1)**을 다시 선택해야 합니다. 활성 소실 후 프로세스를 재시작해도 이 확인 조건은 유지합니다. 오래된 프레임의 유효성을 새 프레임처럼 바꾸지 않습니다.

USB 연결 오류는 주차 상태에서 0 → 1로 재준비하고 앱도 다시 연결합니다. 커널 I/O가 멈춰 해제되지 않으면 정차 상태에서 기기를 재시작해야 할 수 있습니다. `JetlinkStatus`는 준비/오류 상태이며 frame 로그의 `modelV2.jetlink`와 `drivingModelData.jetlink`에 출처·소실·세션·측정값을 남깁니다. C3X QCOM 실기 빌드, 실제 USB 속도, 카메라 픽셀 비교 및 주행 수용은 아직 별도 검증 대상입니다.

위 Android 패키지 절차에서는 지원되는 원본 모델 바이트를 사용해야 합니다. 네이티브 `dev-md` 런타임은 지원되는 앱 선택 모델의 계약도 세션별로 고정합니다. 앱 모델이 바뀌거나 해제되면 해당 세션을 끝내고 주행 중 변경을 자동으로 받아들이지 않습니다. 실행 파일 해시가 없거나 선택한 계약과 다르면 연결 준비를 거부합니다. 원본 이름이나 텐서 형상이 같다는 이유로 다른 실행 파일을 같은 모델로 취급하지 않습니다.
