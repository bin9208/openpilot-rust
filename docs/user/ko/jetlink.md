# Android Jetlink 실험 앱

대상은 갤럭시 탭 S9 울트라 12GB(Android 15 이상)와 comma 3X입니다. 앱은 arm64 Android 9 이상에서 설치 가능하도록 빌드하지만, 다른 기기 호환성과 대상 기기의 실측은 별도 검증 사항입니다. 현재 단계는 모델·연결 검증용이며 차량 사용 승인이 아닙니다.

## 설치와 모델 가져오기

1. 제공된 APK와 SHA-256을 대조한 뒤 APK를 탭에서 엽니다. 파일 앱의 외부 앱 설치 권한이 필요할 수 있습니다.
2. `Carrot Jetlink` → **모델** → **모델 패키지 ZIP 가져오기**에서 준비된 패키지를 선택합니다. 모델은 APK에 포함되지 않으며 내부 앱 저장소에 검증 후 저장됩니다. 가져오기는 모델 용량 외 임시 공간이 필요합니다.
3. 패키지는 `manifest.json`, `model.onnx`, 선택적 `benchmark.frames.bin` 순서의 ZIP입니다. 경로·크기·SHA-256·입출력 형상·상태 연결을 검사합니다. CTV3의 원본 바이트를 보존한 stateful 패키지를 사용합니다. queued 모델은 수치 일치 검증 미완료로 거부합니다.
4. CPU가 초기 기준입니다. NNAPI 선택은 실행 제공자 요청이며 전체 모델의 NPU 가속을 보장하지 않습니다. 실패하거나 일부 연산이 CPU에서 실행될 수 있습니다.

업데이트할 때 앱을 삭제하거나 데이터를 지우지 마세요. 같은 서명으로 만든 APK를 덮어 설치해야 모델 데이터가 유지됩니다. CI 임시 debug APK는 실행마다 서명이 달라질 수 있으므로 배포용 로컬 APK와 섞어 업데이트하지 마세요.

## 정차 상태 벤치마크

**벤치마크** → **100프레임 속도 측정**를 실행합니다. 화면을 켜 둔 채 기다리세요. 준비·워밍업 후 실제 ONNX Runtime 추론 시간을 측정합니다. 입력은 패키지의 합성 프레임을 반복하거나 검은 이미지와 고정 문맥을 사용합니다. 평균/p50/p95/p99/최대값과 50ms 초과 횟수를 표시합니다. 백분위는 최근 2,000개, 평균·최대·초과 횟수는 전체 실행 기준입니다.

**출력 비교 ZIP 저장 (벤치마크 후)**로 첫 입력 묶음의 실제 출력을 저장합니다. 패키지 입력은 최대 100프레임이며 초과하면 가져오기를 거부합니다. ZIP을 PC에서 풀고 `tools.jetlink_model.compare`로 동일 입력의 PC 기준 기록과 비교합니다. **진단** → **진단 보고서 저장**으로 기기/모델/요청 제공자/성능·발열 정보를 저장합니다. 측정값은 실행 시작 당시 모델·제공자를 유지하며 나중에 선택을 바꿔도 바뀌지 않습니다. 발열·메모리는 내보내는 시점의 값입니다. 카메라 영상이나 위치는 진단 파일에 기록하지 않습니다.

측정 시간에는 C3X 카메라 변환과 전체 USB 왕복이 포함되지 않습니다. APK 빌드·합성 입력 성공은 실제 탭 성능, 30분 발열 또는 차량 검증을 대신하지 않습니다.

## USB 연결과 중지

C3X에는 Jetlink가 포함된 브랜치가 필요합니다. 앱만 설치해서는 연결되지 않습니다. 켜고 끄는 설정은 없습니다. 예전 안내의 `Jetlink 모드`(0/1/2)는 없어졌습니다. USB 3 데이터 케이블로 연결하고, C3X가 Jetlink vendor gadget(1209:0001)을 준비한 다음 앱의 **상태** → **comma USB 연결**을 누르고 USB 권한을 허용합니다. 앱은 알림을 표시하는 연결 서비스를 사용합니다. 사용할 모델은 앱에서 불러온 모델입니다.

권한을 거부하거나 케이블을 분리하면 수동으로 다시 연결해야 합니다. **중지** 또는 알림의 **중지**로 서비스를 종료합니다. 재부팅/프로세스 종료 후 자동 연결하지 않습니다. 발열 단계 SEVERE 이상은 작업을 중단하며 식힌 뒤 다시 시도합니다. 메모리 부족·모델 오류는 상태 화면에 표시합니다. 엔진 `ready`는 주행 허용 상태가 아닙니다.

실기 검증 전 확인 항목: APK 설치/회전, 모델 가져오기, CPU 및 NNAPI 출력 비교, USB 권한 거부·분리·재연결, 30분 연속 사용과 발열 상태, 폰 프레임을 잃었을 때의 제어 해제. 이슈 #44/#45/#46/#47의 실기 항목은 결과가 나올 때까지 열어 둡니다.

## C3X가 폰 모델로 넘어가고 돌아오는 방식

폰이 연결돼 모델이 준비되면 C3X는 스스로 폰 모델로 넘어갑니다. 넘어가는 조건은 다음을 모두 만족할 때입니다.

- 내부 모델이 먼저 세 번 이상 결과를 냈고 카메라 보정값을 받았습니다.
- 차량 상태·주행 상태·제어 명령이 0.25초 안에 들어온 유효한 값입니다.
- 차가 완전히 멈춰 있거나, 운전자가 핸들을 잡고 있습니다.

한 번 넘어간 뒤에는 주행 중에 이 조건을 다시 보지 않습니다.

폰 모델을 쓰는 동안 C3X의 내부 모델은 돌지 않습니다. C3X는 카메라 영상을 모델 입력 크기로 줄여 폰에 보내고, 폰의 답을 그대로 게시합니다. 폰의 답은 프레임마다 0.15초까지 기다립니다. 0.05초를 넘긴 프레임은 버리지 않고 쓰며, 로그에 `Jetlink slow frame`으로 남깁니다.

폰의 답이 프레임 주기(0.05초)보다 계속 늦으면 초당 프레임 수가 20에서 내려갑니다. 16 아래로 내려가면 통신 문제 경고와 함께 인게이지가 풀립니다. 폰이 뜨거워져 추론이 느려질 때 이렇게 됩니다. 폰을 식혀 주세요.

폰 프레임을 잃으면(0.15초 초과, 케이블 분리, 잘못된 응답) 다음과 같이 됩니다.

- 그 프레임부터 내부 모델이 이력을 비운 상태에서 다시 답합니다.
- 5초 동안 통신 문제 경고가 떠서 인게이지가 풀립니다. 제어 중에 모델이 조용히 바뀌지 않게 하기 위한 동작입니다.
- 5초 뒤부터 위의 조건(정차 또는 핸들을 잡은 상태)이 맞으면 다시 폰 모델로 넘어갑니다. 따로 눌러 줄 것은 없습니다.

주행 중에는 USB gadget을 다시 구성하지 않습니다. 커널 I/O가 멈춰 해제되지 않으면 정차 상태에서 기기를 재시작해야 할 수 있습니다. 주행 중 USB 연결이 물리적으로 끊긴 뒤 다시 붙지 않은 사례가 있으며 원인은 아직 모릅니다.

## 기록에서 확인하기

- 주행 기록(rlog)의 `drivingModelData.jetlink`와 `modelV2.jetlink`에 프레임마다 출처(`native`/`jetlink`), 단계(`ACTIVE`/`PREPARING`/`READY`/`LOST`), 걸린 시간(`executionMs`)이 남습니다.
- 같은 기록의 `runtimeTiming` 이벤트에 초당 요약이 남습니다. `modeld`의 `jetlink_warp_ms`·`jetlink_handoff_ms`·`jetlink_roundtrip_ms`·`jetlink_parse_ms`, `jetlinkd`의 `usb_exchange_ms`와 폰이 보고한 `server_gpu_ms`·`server_queue_ms`·`server_total_ms`입니다. `usb_exchange_ms`에서 `server_total_ms`를 뺀 값이 USB 전송에 든 시간입니다.
- 연결 상태와 실패 사유는 `/dev/shm/carrot-jetlink.json`과 `/dev/shm/carrot-jetlink-model.json`에 있습니다.

이 안내의 수치는 코드의 값입니다. 폰 모델로 주행하는 것은 아직 차량에서 충분히 확인되지 않았습니다.
