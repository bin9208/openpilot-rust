# Native u-blox receiver and decoder

Issue [#129](https://github.com/bin9208/openpilot-rust/issues/129), full-runtime [#1](https://github.com/bin9208/openpilot-rust/issues/1). Source: unchanged `openpilot/system/ubloxd/{pigeond,ubloxd,ubx,binary_struct,gps,glonass}.py` at `0893b81c`. Original licensing and history remain intact.

`rust/crates/ublox` supplies continuous `openpilot-pigeond` and `openpilot-ubloxd` binaries. The receiver opens the source terminal, configures 9600/460800 baud and raw VMIN=0/VTIME=0 semantics, performs the source power/configuration/backup/time/AssistNow sequence, and publishes `ubloxRaw`. The decoder consumes non-conflated raw packets, preserves checksum/resynchronization state, and publishes complete `gpsLocationExternal` and `ubloxGnss` records.

Typed compiled field tables replace the reflection-based binary reader on the consumed runtime path. `generate_ublox_layouts.py` derives those tables and exact receiver command bytes from unchanged source schemas. Python is a development generator/oracle dependency only; the native binaries do not invoke Python. The unused generic Python reflection API is not a native public API. GPS subframe 4/ionosphere data remains unpublished, as in the source.

## Preserved behavior

- Leading zero serial data causes full reinitialization using the existing descriptor. There is no invented reopen loop. Empty reads sleep 1 ms. Reads accumulate at most 4096 bytes through 64-byte VTIME reads.
- NACK returns false, and `send_with_ack` intentionally ignores that boolean. Only timeout triggers the ten initialization retries. The top-level initializer continues after a false initialization result. Reset attempts retain the five-try backup deletion verification. Almanac saves remain strictly more than 300 seconds apart and only follow a nonempty publication.
- SIGINT sends controlled GNSS stop then turns power off. GPIO safe-boot remains high. Uncaught serial/other failures are not converted to reconnect success. System time bounds reuse the existing timed port, Params uses the typed string boundary, and AssistNow retains its query fields, per-socket five-second timeout, response splitting and caught failures.
- Framing retains the source's handling of split preambles, discarded garbage, empty chunks, partial payloads, checksum failures and unknown message types. Malformed frame parsing is skipped per frame without clearing unrelated caches or suppressing a later valid frame.
- NAV-PVT timestamps retain invalid-date fallback, day/second arithmetic, nanosecond truncation and Float32 velocity rounding. Unknown measurement/satellite/antenna enums fail as in the source; unknown hardware configuration source maps to undefined.
- GPS cache assembly retains IODE consistency, signed field interpretation, source GPS pi, week rollover and cache clearing. GLONASS retains sign-magnitude conversion, unknown satellite storage, frequency grouping, superframe matching, the strict greater-than-ten-second stale threshold and deprecated fields.

Normal defaults use the existing native msgq, logging and hardware boundaries. An alternate `--root` requires an isolated `rust-probe-*` namespace and maps serial/GPIO/Params/systemd paths into an owned fixture tree. `--assist-url` supports the local HTTP fixture. Manager catalog availability changes; production process descriptors and selection remain unchanged. QCOM GNSS is outside this component.

## Focused verification

```sh
export CARGO_INCREMENTAL=0
cargo build --manifest-path rust/Cargo.toml -p openpilot-ublox --bins --examples --locked -j2
PYTHONPATH=. python rust/tools/check_ublox.py --trace rust/target/debug/examples/ublox_trace --evidence /tmp/ublox-evidence
PYTHONPATH=. python rust/tools/check_pigeon.py --trace rust/target/debug/examples/pigeon_trace --evidence /tmp/ublox-evidence
PYTHONPATH=. python rust/tools/check_ublox_serial.py --binary rust/target/debug/examples/ublox_serial --evidence /tmp/ublox-evidence
PYTHONPATH=. python rust/tools/check_ublox_daemons.py --target rust/target --evidence /tmp/ublox-evidence
```

Use Rust 1.94.0, the existing native msgq/cereal prerequisites, Clang with ASan/UBSan support, and Python `pycapnp numpy pyserial pyzmq zstandard`. No registry version is upgraded. To regenerate development tables, run `PYTHONPATH=. python rust/tools/generate_ublox_layouts.py` followed by Cargo fmt; the synthetic Miri input is generated by `PYTHONPATH=. python rust/tools/ublox_fixture.py`.

The decoder gate compares complete decoded cereal records and framing state over 39 chunks, 57 frames and 17 publications against the unchanged source parser and actual source message constructor. Nine receiver policy scenarios compare every send/receive/baud/power/sleep/log/time/Params/AssistNow boundary in successful initialization, ignored NACK, timeout exhaustion, AssistNow failure, reset retries and almanac save outcomes.

The source `TTYPigeon` and native serial reader run against separate owned PTYs with identical input. Their complete termios state at both baud rates, empty/binary reads and writes match. This gate initially found extra input-baud bits from Rust's combined speed setter; the port now uses the source-compatible output speed update and the full PTY scenario passes. The identical production C++ DTR/RTS function runs under ASan/UBSan with controlled ioctls, covering call order, EINVAL/ENOTTY suppression and EIO propagation. This does not instrument the whole runtime or validate physical serial hardware.

The actual daemon gate inspects `/proc/PID/exe`, runs both native binaries with original msgq peers, drives an owned PTY and a loopback AssistNow server, and compares all 38 decoded publications against the actual source parser fed the captured raw packets. It removes the owned serial pathname before the second initialization: continued publication proves reuse of the open descriptor. It observes the leading-zero warning, two initialization sequences, controlled GNSS stop, exit zero and final GPIO fixture values. Source/native comparisons exclude only wall-clock-dependent publication timestamps in this real-time scenario; the deterministic decoder gate compares those too.

The source-checked binary corpus also runs under default and strict-provenance/symbolic-alignment/preemption Miri with native features disabled. Miri cannot execute the C++/kernel boundary; its proof scope is safe Rust framing, binary parsing, cache assembly and serialization. Evidence is recorded under `.omo/evidence/ublox-129/` in the parent workspace, including source/native packets and traces, PTY states, ioctl sanitizer logs, actual process/serial/HTTP/IPC captures, Miri and focused lint/build logs.

After the filesystem recovery on 2026-10-01, the preserved package rebuilt and all four focused gates passed again without runtime changes. Recovery captures are in `.omo/evidence/ublox-129/resume/`: 39 chunks/57 frames/17 decoder publications, all nine receiver scenarios, complete PTY parity with ioctl sanitizers, and 30 `ubloxGnss` plus eight `gpsLocationExternal` daemon publications. The second initialization again used the existing descriptor after pathname removal; SIGINT exited zero with controlled stop and GPIO power off. Focused formatting, Ruff, syntax and source-oracle integrity checks passed. Earlier Miri/clippy artifacts were retained rather than rerunning their completed matrices; exact-SHA CI remains the parent integration gate.

## Remaining acceptance

External dependencies remain explicit: Linux terminal/GPIO APIs, CXX for two modem-line ioctls, original msgq, native logging, Params, clock validation and HTTP/TLS transport. No real serial receiver, GPIO, desktop peripheral, GNSS capture or vehicle was accessed. No project-owned u-blox runtime is delegated to Python. Physical baud/power behavior, receiver firmware, satellite reception, loaded timing, ARM/AGNOS ABI and device acceptance remain unvalidated. Parent integration owns exact-SHA Actions and generic ARM builds. Complete normal startup/log upload is still a whole-runtime gate, not satisfied by this component.
