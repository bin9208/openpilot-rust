Therefore update the canonical header and generated consumers coherently; do not hand-maintain a divergent Rust registry. Source header adds transient ImpactDashcam params, cleared legacy Jetson update flags, SignalAssistMode, VehicleNaviDecelCancel plus per-kind defaults/SectionAvgControl, HyundaiCanfdClusterDirectTx, BlinkerLatchedTurn/LaneChangeLeverWait, TeslaWakeOnCAN, DriverMonitoringEnabled/SessionDisabled/Mode and CarrotVisionEnabled; removes three YouTube settings; changes OnnxBsdThreshold default 45 to 94. ## Evidence-supported optimization exceptions

1. Python process spawning: `process-supervision/src/{launch,exec}.rs` already launches executables. Do not add Python `spawn=True` plumbing; implement readiness/restart decisions and test manager responsiveness instead.
2. Python/Cython drawing acceleration: `ui-application/src/onroad/model_renderer/` is Rust and has native loops. Do not recreate Cython wrappers solely for speed. Retain geometry/text/render correctness deltas and benchmark only if a measurable Rust bottleneck remains.
3. PSS infrastructure partly exists: `runtime-core/src/procfs.rs` has identity-keyed proportional-memory cache, smaps_rollup/smaps fallback and 20-cycle refresh; `proclogd/src/wire.rs` exports mem_pss/anon/shmem. This supports skipping a duplicate parser. It does **not** implement latest spread sampling: current `smaps_cycle == 0 || new identity` refreshes existing processes together, so `1cd1b2c6` workload staggering still needs comparison/porting with read-count/freshness tests.
4. Do not port obsolete YouTube optimization or superseded UI cache experiments: final source removes them. Their remaining Rust implementations are removal work.
