# dev-md native DM2 port and validation

Issue #338 only; experimental branch `dev-md`. No dev/main integration, device connection or deployment. Source final behavior is `carrot-source/carrot-wip` at `e8e152dbcfd9574a1791ed12026d1880e87689b3`.

## Native implementation

`rust/crates/monitoring/src/dm2.rs` layers source `dm2.py` over the existing Rust stock policy. Mutable timeouts retain elapsed attention across camera/mode/context changes; orange/red alerts, terminal counts and lockout survive budget changes. Experimental interaction grace, pose/phone thresholds, forward-attention recovery, interaction credit, automatic wheel fallback and continuous parking reset are native. The original stock interface keeps its stock defaults.

`monitoring/src/context.rs` ports source `dm2_context.py`: persistent moving-traffic association, bounded strict hold and clear-road bonus, three physical CANCEL presses, automatic CANCEL echo/release filtering, pedal/button edges, steering-touch reconnect semantics, and two-second camera recovery.

`rust/crates/dmonitoringd` runs the final dispatcher as an actual native daemon, tagged `openpilot.selfdrive.monitoring.dm2d` for manager diagnostics. It keeps camera/monitor processes alive while monitoring is disabled or paused; emits monitoring state every 50 ms through absent-camera polls; drains nonconflated carState/carControl queues before processing physical responses; consumes native Bluetooth attention journal events; uses the route clock/model poll during replay; waits for current CarParams onroad. Stationary soft hold freezes monitor state and suppresses warnings without writing enable/session Params. Camera loss selects interaction monitoring; it does not silence warnings.

Consumed Params: `DriverMonitoringEnabled`, `DriverMonitoringSessionDisabled`, `DriverMonitoringMode`, `AlwaysOnDM`, `IsDriverViewEnabled`, `IsRhdDetected`, `DriverTooDistracted`, `EnableCornerRadar`, `SpeedFromPCM`, `CarParams`, `IsOnroad`. Writes are session disable on gesture and learned RHD at the source cadence. Parent integration owns boot migration, manager predicates, settings UI, Bluetooth journal production, forceDecel/HUD/event consumers. No native camera inference provider has been replaced by this policy port; existing driver-model/calibration/model/radar providers remain explicit inputs.
