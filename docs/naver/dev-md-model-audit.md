## Already present foundations and limits on skipping work

* Rust Jetlink already has framing tests, socket/daemon/FFS tests, state transitions, fallback plumbing and per-message status (`jetlink/tests`, `drivingd/src/jetlink.rs`). Reuse these rather than re-porting baseline v2. The hard-coded version/contract above proves final-source delta remains.
* Rust eGPU delivery already verifies precompiled catalog/checkpoint/PKL, supports packaged/downloaded artifacts, bounded boot validation and healthy internal startup fallback (`usbgpu/src/model_delivery/{catalog,precompiled,boot}.rs`, `worker_artifact.rs`). Reuse this verified-source structure; it does not establish background runtime recovery or final model-layout parity.
* Rust camera already uses `staggered: false`, preserves per-camera geometry/exposure/state and a single owner. This matches baseline invariants and should remain. The single-fd synchronous event loop is direct counter-evidence for skipping the new async driver fence isolation.
* Rust health parsing already preserves older ignition and safety fields. The new field shifts all old fields after ignition by one byte and increases the packet to 59 bytes: update version negotiation and decoding together, and never treat wake as onroad ignition.
* No optimization delta in this scope is justified as completely redundant solely because it is written in Rust. Source hot-path changes (`86d1e215`), GPU-wait yielding, shared NV12 warp and timeout fixes require specific call-graph/allocation/wait-equivalence evidence before omission. Existing code/test filenames are evidence of foundations only; no tests were run by this audit.

## Firmware preservation requirements

`b1485d40` records actual applied CAN mux/harness mode, snapshots successful FDCAN configuration, and preserves healthy live H7 controllers only during narrowly gated diagnostic-to-Hyundai policy transitions. Pending hardware TX, bus/clock/silent/loopback changes, bus-off/error states and failed initialization prohibit preservation. It clears old-policy software TX and bounded hardware RX snapshots inside the transition critical section and otherwise retains full reinitialization. Port this exact predicate and tests; do not broadly suppress controller resets.

`a3fbd86f` separates Tesla power evidence from SOM wake. Standard-frame checksum and consecutive rolling-counter validation are mandatory for power/gear/cabin changes, invalid frames break sequences, power expires, and only the dedicated wake build enables Tesla wake. Bootkick responds to rising wake separately from ignition. Health reports wake independently. `094b52ca` changes timer interrupt-rate registration to 2 and corrects sound register checks; these are firmware correctness fixes, not host optimizations. Preserve Panda independent safety behavior throughout conversion.

## Scale and acceptance

This is several independent workstreams, not a small model update: model runtime/recovery and artifacts; v2/v3 vehicle transport/direct warp; external-host/server/provisioning tools; live/offline signal algorithms and assist consumers; asynchronous camera ownership; firmware/ABI; encoder/removal integration. The source diff contains 233 changed files and approximately 204,476 added / 178 removed lines across modeld, Jetlink tools, signal analysis/training and Panda board (includes generated/large content; not a labor estimate). Expect large feature-sized ports for Jetlink host/tooling and signals, medium-to-large model integration/recovery, and bounded but safety-sensitive camera/firmware/encoder changes.

Require deterministic differential traces for model outputs/recurrent state and signal frame cadence, wire fixtures for both Jetlink versions and Panda ABI, failure/timeout/reconnect/teardown tests, and exact-source asset verification before any completion claim. Device boot/record/upload and driving acceptance remain separate later gates; this audit authorizes no deployment. Track outstanding feature groups in #338, without closing on host checks alone.
