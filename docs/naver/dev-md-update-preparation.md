# dev-md 업데이트 준비·재선택

이슈: [#346](https://github.com/bin9208/openpilot-rust/issues/346). 기준 소스:
`9161ddb73915899a99f72d839367c8669895daf4`. 구현 및 검증 진행 중.

사용자는 시동이 꺼지면 기기 전원도 꺼지는 구성에서 주행 상태와 관계없이 업데이트를
준비하고 다음 재부팅에 적용할 수 있어야 한다고 요청했다. 부모 에이전트가 원인 분석,
설계와 최종 검토를 맡았다. 초기 회귀 테스트는 Qwen3.8 Q6_K_L의 명시적 `xhigh`로 작성했으며,
이후 사용자의 “스탑 그냥 너가 다해” 지시로 Qwen 작업을 모두 종료하고 부모가 직접 구현과
나머지 검증을 수행한다.
기존 Athena 미커밋 변경 및 #296 도구 변환은 포함하지 않는다. 통합 대상은 `dev-md`다.

## 확인한 원인과 변경 계약

- 설치기의 준비·완료·기존 overlay 채택·부팅 적용이 모두 저장된 `IsOnroad=0`에 의존했다.
  부팅 초기에 이전 주행 값이 남아 있어도 적용이 거절됐다. 이 상태 조건을 제거한다.
- 준비된 `finalized`가 있으면 다른 커밋 준비가 거절됐다. 새 후보가 완전히 검증된 뒤
  디렉터리를 원자 교환하여 재선택한다. 새 후보가 실패하면 기존 후보를 유지한다.
  같은 커밋의 브랜치/분리 HEAD 선택도 요청대로 반영한다.
- 자동 업데이터는 기존 준비 후보가 있다는 이유로 초기화를 거절하고, fetch 전에 기존
  완료 표시를 지웠다. overlay 작업 디렉터리만 재생성하고 완료 후보는 설치기의 교체까지
  보존한다. 중단된 적용 journal은 부팅 복구 대상이므로 준비와 동시에 처리하지 않는다.
- 설치·웹·복구의 저장소 주소 허용 목록을 제거하고 사용자가 설정한 origin을 보존한다.
  UI 신호 전송은 파일명 강제를 없애고 관리자가 소유한 PID와 실행 파일의 실제 동일성을 확인한다.
- 준비는 활성 HEAD·실행 파일·주행 제어를 교체하지 않는다. 적용은 기존의 새 부팅 경계에서
  수행한다. 해시/소스 일치, 손상 검사, 공간 검사, 잠금, 원자 교환과 중단 복구는 유지한다.
  이 작업은 주행 중 강제 재부팅이나 현재 실행 중인 제어 프로세스 교체를 추가하지 않는다.

## 실행 순서와 검증

1. 실제 Git/오프라인 패키지 fixture에 준비·부팅 적용·재선택·실패 보존 테스트를 추가하고
   기존 코드에서 기대한 원인으로 실패하는지 확인한다.
2. 설치기 트랜잭션, 자동 업데이터, 웹/복구, UI 신호의 제한을 수정한다.
   부모가 직접 구현과 검토를 수행하고 손상·활성 프로세스·복구 검사를 함께 실행한다.
3. 변경 패키지 호스트 검사와 영향을 받는 ARM 빌드를 실행한다. 이슈 브랜치와 dev-md의
   정확한 SHA에 필수 CI를 확인한다. dev/main에는 통합하지 않는다.
4. 동일 소스의 AGNOS 런타임과 설치기를 빌드·봉인·사전 릴리스로 발행한다.
   공개 산출물을 다시 받아 기존 설치 경로로 검증한다. 기기 설치·주행 검증은 사용자 소관이다.

## 결과

검증 후 정확한 커밋, CI 및 릴리스 링크를 추가한다. 호스트 검증을 실차 확인으로
표현하지 않으며, 사용자 기기 수용 전에는 해당 완료 조건을 열어 둔다.

## 검토 자료

- [Linux rename(2)](https://man7.org/linux/man-pages/man2/rename.2.html): 기존의 비어 있지 않은
  후보 디렉터리를 교체할 때 `RENAME_EXCHANGE`로 이름을 원자 교환한다.
- [Linux fsync(2)](https://man7.org/linux/man-pages/man2/fsync.2.html): 파일 동기화와 디렉터리
  항목 동기화를 구분한다. 새 후보의 내용과 완료 표시를 동기화한 뒤 교환하고, 두 부모
  디렉터리도 동기화해야 재부팅 복구 경계를 검토할 수 있다.

추가 화면 조사: 큰 화면 Software는 주행 중 Download 항목을 숨기고 `IsTestedBranch`에서
브랜치 선택을 숨겼다. 작은 화면 Device 업데이터도 주행 중 버튼 전체를 막았다. 확인·다운로드와
브랜치 선택을 사용할 수 있도록 함께 바꾸며, 작은 화면의 완료 상태는 다음 재시작 적용으로
표시한다. 기존 UI의 설치 버튼은 실제 재부팅 동작이므로 다운로드와 구분해 검증한다.

준비 후보를 다시 선택할 수 있게 하는 변경은 자동 반복 작업이 사용자의 보류 중인 선택을
덮어쓰는 동작을 추가해서는 안 된다. 자동 반복은 완성 후보가 있으면 그 선택을 보존하고,
사용자가 새 다운로드를 요청하면 교체 준비를 허용하는 경계도 검토한다.

추가 관리자 조사: `manager-catalog::Predicate::Updated`도 `!started && SoftwareMenu`였고,
원본 Python `enable_updated`에서 물려받은 조건이었다. 주행 중 요청을 받을 데몬이 살아 있도록
시동 조건을 제거한다. 사용자의 `SoftwareMenu`/`DisableUpdates` 명시적 선택은 보존한다.
이 사용자 요청에 따른 차이는 기존 원본 비교에서도 별도 예상 결과로 검증한다.

초기 호스트 준비 검증: 설치기·업데이터·런처·웹·복구·UI의 `cargo test --no-run --locked` 성공
(2분 14초). 별도 Xvfb `:97`과 소스 해시가 검증된 호스트 raylib 플러그인으로 기존 Software
실제 렌더링을 재현했다. 주행 상태에서 Download 행이 없고, 같은 자리의 클릭은 브랜치 선택을
발생시켰다. 이는 수정 전 재현이며 수정 후 성공 증거가 아니다. 원본 캡처와 로그는 비공개
작업 디렉터리에 두며 트랙에는 포함하지 않는다.

직접 구현 후 확인: 설치기 새 회귀 5개는 기존 코드에서 기대한 이유로 실패했다
(나머지 47개 성공). 준비·선택·부팅 상태 제거 후 설치기/관리자 검사는 통과했다.
추가로 다른 이름의 remote, 다른 로컬 브랜치의 upstream과 URL 치환 설정을 보존하고,
같은 SHA 재선택은 봉인된 준비 패키지 캐시를 재사용하여 다운로드를 반복하지 않는다.

자동 업데이터의 준비본 보존 테스트 2개도 기존 코드에서 실패했다. 새 코드는 초기 overlay
재생성과 fetch 실패에도 완료 표시·기존 후보·UpdateAvailable을 보존한다. 자동 반복은
완성 후보를 보존하고 명시적 새 다운로드 요청은 재선택할 수 있다. 웹 자동 반복도 이미
준비된 선택을 보존한다. 활성화 journal, 잠금 및 실제 실행 중인 이전 런타임 소유자는
기존대로 복구/새 부팅 경계를 유지한다.

웹/복구의 임의 origin 주소 제한 및 복구의 로컬 변경 사전 거절을 제거했다. 준비 중에는
로컬 변경을 포함한 활성 checkout을 수정하지 않으며, 실제 부팅 교체는 이전 checkout 전체를
rollback 디렉터리에 보존한다. 명시적 저장소 초기화 동작의 기본 origin 복원은 유지한다.

화면 검증 명령은 `python3 rust/tools/check_ui_update_preparation.py --binary <product_render>
--output <private-output> --display :97`다. 수정 전 주행 중 확인 요청이 전달되지 않는 것을
재현했고, 수정 후 영어/한국어 16개 실제 렌더/입력/Params 시나리오가 통과했다. 이 검사는
기존 UI CI에도 연결했다. 다운로드·브랜치 선택과 실제 재시작을 구분해 검증하며, 테스트는
실제 차량 제어·재부팅을 수행하지 않는다. 새 부팅 적용 조건은 차량 상태와 무관하다.

로컬 최종 검증: 변경한 7개 패키지의 `cargo test --locked --lib --tests`에서 **212개 통과**,
기존 무시 항목 5개 유지. 별도 실행형 웹/복구 통합 fixture도 성공했다. 임의 origin의 실제
Git 준비와 패키지 실패 보존, 로컬 수정이 있는 복구 준비, 다른 이름/별칭의 업데이터 PID
동일성, 다른 remote·upstream 보존과 같은 SHA의 네트워크 없는 캐시 재선택을 포함한다.
같은 패키지의 `cargo clippy --locked --all-targets -- -D warnings`와 fmt/diff 검사도 성공했다.
영어/한국어 실제 UI 시나리오는 재시작 버튼 양쪽 상태까지 확장하여 **20개 통과**했다.
기기 설치·실차 확인은 수행하지 않았다. 이후 정확한 원격 SHA, Actions 및 AGNOS 패키지
검증 영수증은 이슈 #346에서 계속 기록한다. 문서만으로 배포 완료를 의미하지 않는다.
